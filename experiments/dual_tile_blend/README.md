# Experimental shared-forward spatial tile blending

This isolated module tests **one hypothesis**: average overlapping raw logits before activation, while retaining the same FP32 Hann weights, tile 512/overlap 64, rot4 probability ensemble and scalar 0.35. It changes no production package, immutable 6d evaluator, released model, frozen selection or TEST result. No real evaluation was executed. The implementation is suggested by a pre-existing operator difference, not selected from TEST scores.

`dual_probabilities` makes exactly one shared model call per tile, in the frozen order. The existing control's GPU joint activation, FP32 weights/additions and conditional/joint conversion sequence are retained. The alternative adds a FP32 raw-five-logit accumulator, normalizes spatially, and uses the same joint activation on the same device. Each view is then inverse-aligned and combined as **joint probabilities** across rot4. It never averages view logits or unweighted conditional AV. No four-view stack or probability-map disk cache is used.

`stream_counts` is a thin, under 100-line scorer wrapper, not an execution CLI or eligibility replacement. It requires full 770 VAL metadata, a caller-supplied checked original BEST50 payload (`521b8881d1b2c69a7395be6687a8b86581838e3f5dbb004a150333d454132cea`), exact original control-reference bytes (`0a5c65e6ecd0ceef68bba554504f0d2e2222905d5ebf27813b07242cb3e7aa0f`) and byte-exact 7be scorer using the same frozen unified module. It calls dataset.sample once per photo and reuses the existing photo_counts/aggregate functions twice. Missing/unknown class validity and annotation-source traces remain unchanged. It returns count dictionaries and explicit equality for all six original control fields, not ordinary freezeable evidence. A control mismatch must be preserved and prevents interpreting the operator contrast; it never authorizes another forward.

A separately reviewed bounded operation must still bind original checkpoint bytes, genuine curated completion/role/coverage, source/runtime, manifest/full-image preprocessing and original reference before model/data access. This module loads no model or dataset path and has no launcher. No existing final gate accepts its new experimental descriptor. The original checkpoint was trained on 2529 photos/5700 annotations; no training, threshold grid, TTA grid, winner selection or deployment is added.

## Bounded memory and limitations

VAL metadata max prepared frame is 1000×1397. One five-channel FP32 frame is 26.65 MiB; dual per-view sums plus shared weights are 58.62 MiB, and both running rot4 sums 53.29 MiB. Explicit releases keep prediction buffers within a conservative 48-plane estimate (~255.8 MiB plus tile temporaries), excluding existing model/data/allocator overhead. Same-device full-frame activation adds at most ~74.6 MiB GPU pointwise buffers, beyond unchanged tile inference. Estimates are not measured process/GPU peaks for real inference.

Sharing forwards is not free: raw-logit D2H adds up to 107.4 GiB traffic for all 770 VAL photos, and full-frame GPU activation adds roughly 113.5 GiB roundtrip traffic. Runtime needs a later bounded observation. Logit pooling can add or remove masks at 0.35; it has no guaranteed precision/recall direction.

This is **not an original 4-net port**. Original vessel uses 320/40 with float64 logit blending and a different convolved window/traversal; universal/disc0 use 288/36 and 192/24. Original calibration/restoration, binary strict-logit threshold, architecture and weights also differ. Here only spatial blend space changes; all original pipeline claims remain separate.
