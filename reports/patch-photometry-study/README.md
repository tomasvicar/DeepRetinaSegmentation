## Photometry contract and evidence required before any NN run

The implementation is independently in preparation; the actual serialized descriptor is authoritative. `raw` must remain byte/RNG-identical and keep raw canonical/cache bytes unchanged. Opt-ins apply once to a **full prepared image after25ppd geometry and before crop, augmentation, fallback or tiling**, through the same TRAIN/VAL/raw-inference path. A transform may recur after LRU eviction; this is not necessarily one computation for the entire training run.

* `clahe_hsv_v1`: RGBfloat32/255→HSV, CLAHE on V with requested kernel250×ppd/55, clip0.005,256bins→RGB, clipped uint8 truncation. At25ppd the requested kernel is113.636…; record actual integer/minimum/dimension rules and backend version explicitly, not just the floating request.
* `legacy_lc_clahe_v1`: existing Python FOV boundary extrapolation, Gaussian background division/offset with sigma80×ppd/55 (36.3636…at25), then HSV-V CLAHE. Existing `local_contrast_and_clahe` already includes background correction; it is not CLAHE-only and is not MATLAB-equivalent ([code](../../src/deepretina/legacy/preprocessing.py)).
* **After either operator restore original prepared raw RGB outside the canonical image-derived FOV**: `where(fov,processed,raw)`. Thus outside-FOV pixels match all arms. Never use annotation statistics/valid-label masks to choose intensity transforms. Require a genuine FOV asset with shape/encoded-byte hash for every2529TRAIN+770VALphoto before admission; missing or ambiguous assets require an exact source/photo/count scope report and block opt-in NN admission, rather than invoking a GT-derived or silent fallback.

Required evidence: descriptor/backend/source hashes; exact integer kernel rules; no in-place modification of shared raw RGB/cache; bounded profile-aware cache; constant/nonfinite/background-zero behavior; mask/valid/annotation bytes unchanged; exact default raw outputs/RNG; the same prepared full-image tensor through TRAIN, VAL and raw inference; crop/fallback/tile consistency; and bounded actual TRAIN sanity/performance with no TEST. Measure full-image CPU transforms/cache misses, loader waits and RSS as well as GPU time/VRAM. CLAHE can become a CPU bottleneck even with an unchanged fast raw cache. No per-crop or per-tile contrast adaptation: it would change a pixel's input with the crop/tiling grid and break the intended train/inference identity.
