## Remaining edge cases and verification limits

A pure metadata counterexample shows that a new TRAIN alias of an existing TRAIN photo receives a new `split_group_id` instead of inheriting the frozen parent's group. It does not cross splits or duplicate the photo used by the current unified loader, but it misrepresents group metadata. Reuse the unique existing parent group in a future helper revision; fail for explicit review if a new patient/photo bridge joins multiple old group IDs, even within TRAIN. The data owner reports zero parent aliases in the new TRAIN audit, so no occurrence in the current artifact is established. A future inherited-parent alias must also state that canonical geometry is inherited if its declared new-source angle differs from the preserved parent frame.

`cp -a` retains source directory permissions; a physically read-only parent image/mask directory would cause appending to fail unless only the child directory is made owner-writable. The actual clone and initial DRIONS appends have already succeeded, so this is not a current launch blocker. Existing tests cover external-inode separation, frozen-row/heldout alias rules, official TEST retention, camera policy selection and a tiny complete append; they do not prove every real source polygon or exact future alias graph. This reviewer did not rerun the already reported36 focused tests or read real TEST arrays. Actual terminal schema2, old-row/pixel preservation, duplicate-photo grouping, TEST membership and supervision-support receipts remain required.
